# XML / Views: building from the dealt tokens

Contents: 1 Theme and color wiring, 2 Fonts and text appearances, 3 Spacing and adaptive resources, 4 Components, 5 Edge-to-edge, 6 Splash, launcher icon and manifest, 7 Motion, 8 Rules

Confirm attribute and style names against the project's Material Components version. Keep existing package, style and resource names; add, do not rename, unless asked.

## 1. Theme and color wiring

`scripts/deal.sh` writes `dealt_colors.xml` (light), a night copy for `values-night/`, and `dealt_themes.xml` containing `Theme.App.Dealt` (Material 3 DayNight parent) with every color role and the five shape corners wired in. Merge them, then either point the application theme at the dealt theme or make your app theme inherit it:

```xml
<style name="Theme.App" parent="Theme.App.Dealt" />
```

- Remove the template's purple `colors.xml` entries and any `Theme.MyApplication` leftovers.
- `values-night/` carries the dark values for the same names; do not hardcode light colors in layouts.
- `surfaceContainer*` attributes need a recent Material Components; if a build error names an unknown attribute, remove that line and use `colorSurfaceVariant` or `colorSurface`.
- Dynamic color is opt-in: call `DynamicColors.applyToActivitiesIfAvailable(this)` in `Application.onCreate()` only if the app is system-feel (see `material3-theming.md`).

## 2. Fonts and text appearances

Create a font family resource per dealt font (`res/font/`), either bundled:

```xml
<!-- res/font/inter.xml -->
<font-family xmlns:android="http://schemas.android.com/apk/res/android">
    <font android:fontStyle="normal" android:fontWeight="400" android:font="@font/inter_regular" />
    <font android:fontStyle="normal" android:fontWeight="500" android:font="@font/inter_medium" />
    <font android:fontStyle="normal" android:fontWeight="600" android:font="@font/inter_semibold" />
</font-family>
```

or downloadable (needs Google Play services and the `com_google_android_gms_fonts_certs` array generated by the Android Studio font tooling):

```xml
<font-family xmlns:app="http://schemas.android.com/apk/res-auto"
    app:fontProviderAuthority="com.google.android.gms.fonts"
    app:fontProviderPackage="com.google.android.gms"
    app:fontProviderQuery="name=Inter"
    app:fontProviderCerts="@array/com_google_android_gms_fonts_certs" />
```

Map the pairing onto the Material 3 text appearances through the theme: display and headline use the display family, everything else the body family.

```xml
<style name="TextAppearance.App.HeadlineLarge" parent="TextAppearance.Material3.HeadlineLarge">
    <item name="fontFamily">@font/plus_jakarta_sans</item>
    <item name="android:fontFamily">@font/plus_jakarta_sans</item>
</style>

<style name="TextAppearance.App.Numeric" parent="TextAppearance.Material3.DisplaySmall">
    <item name="android:fontFeatureSettings">tnum</item>
</style>

<style name="Theme.App" parent="Theme.App.Dealt">
    <item name="textAppearanceHeadlineLarge">@style/TextAppearance.App.HeadlineLarge</item>
    <!-- repeat for the other display/headline styles, then title/body/label with the body family -->
</style>
```

Use `android:textAppearance="?attr/textAppearanceTitleMedium"` in layouts; never `android:textSize` literals or `android:fontFamily` per view. Use `TextAppearance.App.Numeric` (tabular figures) on balances, timers and scores.

## 3. Spacing and adaptive resources

```xml
<!-- values/dimens.xml -->
<dimen name="space_xs">4dp</dimen>
<dimen name="space_s">8dp</dimen>
<dimen name="space_m">16dp</dimen>
<dimen name="space_l">24dp</dimen>
<dimen name="space_xl">32dp</dimen>
<dimen name="screen_margin">16dp</dimen>
<dimen name="content_max_width">600dp</dimen>

<!-- values-sw600dp/dimens.xml -->
<dimen name="screen_margin">24dp</dimen>
<dimen name="content_max_width">840dp</dimen>
```

- Layouts use these names, never raw `13dp`.
- Provide `layout-sw600dp` (or `layout-w600dp`) and `layout-w840dp` variants for screens that have list and detail, and switch navigation: `BottomNavigationView` on compact, `NavigationRailView` on larger widths.
- For list-detail on larger screens, `SlidingPaneLayout` (AndroidX) or two fragments in an `FragmentContainerView` pair. Preserve selection across rotation and resize.
- Cap line length: wrap reading content in a container with `android:maxWidth`-style constraints (for example `ConstraintLayout` with `layout_constraintWidth_max="@dimen/content_max_width"`).

## 4. Components

Use Material 3 components with their M3 styles, colored by theme attributes:

```xml
<com.google.android.material.card.MaterialCardView
    style="?attr/materialCardViewFilledStyle"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:layout_marginHorizontal="@dimen/screen_margin">

    <TextView
        android:id="@+id/balance"
        style="@style/TextAppearance.App.Numeric"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_margin="@dimen/space_m"
        android:textColor="?attr/colorOnSurface" />
</com.google.android.material.card.MaterialCardView>

<com.google.android.material.button.MaterialButton
    style="@style/Widget.Material3.Button.TonalButton"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    android:text="@string/action_add_account" />
```

- Colors in layouts are theme attributes (`?attr/colorSurfaceContainer`, `?attr/colorOnSurfaceVariant`), never hex.
- Icons: vector drawables from one family, tinted with a theme attribute (`app:iconTint="?attr/colorOnSurfaceVariant"`).
- Top app bar: `MaterialToolbar`; for a large collapsing title use `AppBarLayout` plus `CollapsingToolbarLayout` with `style="?attr/collapsingToolbarLayoutLargeStyle"`.
- Navigation: `BottomNavigationView` for 3-5 destinations (compact), `NavigationRailView` on wider windows.
- Lists: `RecyclerView` with `ListAdapter` and `DiffUtil`; `ListView`/`GridView` only in legacy code.
- Loading: placeholder views (a `SkeletonView` or shimmer library the project already has, or plain rounded `View`s in `?attr/colorSurfaceContainerHigh` with an alpha `ObjectAnimator`), not a bare `ProgressBar` for content.
- Empty state: an `include` layout with a vector drawable, title, body, one `MaterialButton`.

## 5. Edge-to-edge

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    enableEdgeToEdge()
    super.onCreate(savedInstanceState)
    setContentView(binding.root)
    ViewCompat.setOnApplyWindowInsetsListener(binding.root) { view, insets ->
        val bars = insets.getInsets(WindowInsetsCompat.Type.systemBars() or WindowInsetsCompat.Type.displayCutout())
        view.updatePadding(left = bars.left, top = bars.top, right = bars.right, bottom = bars.bottom)
        insets
    }
}
```

Remove `android:fitsSystemWindows` hacks, hardcoded status-bar heights and `windowTranslucentStatus` workarounds. For scrolling lists, apply the bottom inset as padding with `clipToPadding="false"` so content scrolls behind the navigation bar.

## 6. Splash, launcher icon and manifest

Splash (AndroidX `core-splashscreen`):

```xml
<style name="Theme.App.Starting" parent="Theme.SplashScreen">
    <item name="windowSplashScreenBackground">@color/dealt_surface</item>
    <item name="windowSplashScreenAnimatedIcon">@drawable/ic_splash</item>
    <item name="postSplashScreenTheme">@style/Theme.App</item>
</style>
```

Set `android:theme="@style/Theme.App.Starting"` on the launcher activity and call `installSplashScreen()` before `super.onCreate`.

Adaptive launcher icon with a themed (monochrome) layer, in `res/mipmap-anydpi-v26/ic_launcher.xml` (the `<monochrome>` element is used on Android 13+):

```xml
<adaptive-icon xmlns:android="http://schemas.android.com/apk/res/android">
    <background android:drawable="@color/ic_launcher_background" />
    <foreground android:drawable="@drawable/ic_launcher_foreground" />
    <monochrome android:drawable="@drawable/ic_launcher_foreground" />
</adaptive-icon>
```

Replace the template's green `#3DDC84` background and robot foreground with an icon drawn for the app (a simple geometric mark in the primary hue on a surface color is better than a gradient blob). Keep the mark inside the safe zone (the central 66dp of the 108dp canvas).

Manifest UI settings: `android:label="@string/app_name"`, `android:supportsRtl="true"`, `android:enableOnBackInvokedCallback="true"` only when back handling uses supported APIs, and no `screenOrientation="portrait"` lock unless the app truly needs it.

## 7. Motion

Material Components ships transitions (`com.google.android.material.transition`):

```kotlin
// fragment A -> fragment B along the X axis
exitTransition = MaterialSharedAxis(MaterialSharedAxis.X, /* forward = */ true)
reenterTransition = MaterialSharedAxis(MaterialSharedAxis.X, /* forward = */ false)
// in B
enterTransition = MaterialSharedAxis(MaterialSharedAxis.X, true)
returnTransition = MaterialSharedAxis(MaterialSharedAxis.X, false)
```

- `MaterialContainerTransform` for a card that becomes its detail screen (set `transitionName` on both views and `sharedElementEnterTransition`).
- `MaterialFadeThrough` between top-level destinations.
- Use durations from the dealt motion personality (`library/motion.tsv`), and make sure animations respect the user's "remove animations" setting by not forcing durations when the animator duration scale is 0.
- Count-up numbers: `ValueAnimator.ofInt(0, target)` with a `DecelerateInterpolator`, set the text on each update; skip the animation when the duration scale is 0.

## 8. Rules

- No `android:background="#..."`, `android:textColor="#..."`, `android:textSize="..sp"` literals in layouts; theme attributes and text appearances only.
- Start / End instead of Left / Right everywhere.
- Text sizes in `sp` through text appearances; everything else in `dp` from the spacing scale; never `px`.
- Every informative image has `contentDescription`; decorative images `importantForAccessibility="no"`.
- Touch targets at least 48dp.
- Test at font scale 1.5 and 2.0 and in dark mode before calling a screen done (`scripts/shoot.sh` automates the capture).
