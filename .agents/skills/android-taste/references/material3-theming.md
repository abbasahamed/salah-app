# Material 3 theming: roles, type, shape, dark, dynamic color

Contents: 1 Where the dealt palettes come from, 2 Color roles and what they are for, 3 Dynamic color decision, 4 Type scale, 5 Shape and elevation, 6 Dark theme, 7 Contrast, 8 Version notes

## 1. Where the dealt palettes come from

`library/palettes_colors.tsv` holds 13 palettes with 34 Material 3 roles each, for light and dark. They were generated by mapping the Material 3 tone recipe (primary at tone 40 light and 80 dark, containers at 90 and 30, surfaces from a near-neutral ramp, and so on) onto CIELAB lightness and hue, with chroma reduced to stay in sRGB. Every text pair in every palette passes WCAG AA (checked by `scripts/contrast.sh --library`).

They are Material 3 shaped, but they are not the output of Google's Material Color Utilities (HCT). If the user has a specific brand seed, generate the role set with Material Theme Builder or the project's existing tooling and keep everything else from the deal. Either way, run `scripts/contrast.sh --project` on the result.

## 2. Color roles and what they are for

| Role | Use it for | Do not use it for |
|---|---|---|
| `primary` / `onPrimary` | main action, selected state, focal accent | large background areas |
| `primaryContainer` / `onPrimaryContainer` | emphasized but quiet surfaces: selected card, active chip, hero tile | body text color |
| `secondary*` | supporting actions, filter chips, less prominent controls | the main call to action |
| `tertiary*` | rare contrast: badge, highlight, a chart series | routine UI chrome |
| `surface` / `background` | screen background | cards (use a container role) |
| `surfaceContainerLowest` ... `Highest` | layered surfaces: cards, sheets, nav bars; higher number = more emphasis | text |
| `surfaceBright` / `surfaceDim` | bright or dim variants of the screen surface | |
| `onSurface` | primary text and icons | secondary text |
| `onSurfaceVariant` | secondary text, icons, hints | primary content |
| `outline` | borders that must be seen (text field outline, outlined button) | decorative lines |
| `outlineVariant` | dividers and subtle borders | anything that conveys state alone |
| `error*` | errors and destructive confirmation | decoration |
| `inverseSurface` / `inverseOnSurface` / `inversePrimary` | snackbars and toasts | |
| `scrim` | modal scrims over content | |

Rules:
- A foreground role is always used on its own background role (`onPrimary` on `primary`, `onSurface` on `surface*`). Pairs that mix families are where contrast bugs come from.
- Layer with tonal containers: screen on `surface`, grouped content on `surfaceContainerLow`, cards on `surfaceContainer` or `surfaceContainerHighest`, nav bars on `surfaceContainer`. Prefer this to shadows.
- Do not tint text with alpha to fake a role. Use `onSurfaceVariant`.
- Status colors beyond error (success, warning) are not in the Material role set. Define them as an extension with light and dark values and contrast-check them like any other pair.

## 3. Dynamic color decision

The Android Studio Compose template sets `dynamicColor = true` by default. On Android 12+ that replaces your palette with one derived from the user's wallpaper, so a dealt or brand palette disappears for most users. Decide on purpose:

- **Brand-first** (finance, commerce, media, games, anything with a brand): default `dynamicColor = false`. Optionally offer "Use wallpaper colors" as a setting.
- **System-feel** (utilities, simple tools): `dynamicColor = true` is reasonable. Still keep the dealt type, shape, layout and motion so the app has a character.
- **Hybrid:** dynamic roles for surfaces, fixed brand color for the primary accent. This needs care with contrast; check with screenshots on two wallpapers.

Compose:

```kotlin
val colorScheme = when {
    dynamicColor && Build.VERSION.SDK_INT >= Build.VERSION_CODES.S -> {
        val context = LocalContext.current
        if (darkTheme) dynamicDarkColorScheme(context) else dynamicLightColorScheme(context)
    }
    darkTheme -> DealtDarkColorScheme
    else -> DealtLightColorScheme
}
```

Views (Application class): `DynamicColors.applyToActivitiesIfAvailable(this)` from Material Components. Omit it for brand-first apps.

State the choice and the default in the report.

## 4. Type scale

Material 3 has 15 styles. Baseline sizes (sp / line height): display large 57/64, medium 45/52, small 36/44; headline large 32/40, medium 28/36, small 24/32; title large 22/28, medium 16/24, small 14/20; body large 16/24, medium 14/20, small 12/16; label large 14/20, medium 12/16, small 11/16.

Map the dealt pairing like this:
- Display and headline styles: the **display** font (it is where personality lives). Weight: regular to semibold; avoid bold on every size.
- Title, body and label styles: the **body** font.
- Single-weight display fonts (Instrument Serif) only at 28sp and above; never for titles or labels.
- Numbers that align or change (balances, timers, scores, prices in lists): turn on tabular figures (`fontFeatureSettings = "tnum"` in Compose, `android:fontFeatureSettings="tnum"` in XML) on those styles. If the font has no `tnum`, switch those numbers to the mono or body font.
- Sentence case everywhere. No ALL CAPS in labels, no letter-spaced uppercase eyebrows unless it is the signature.
- Respect user font scaling. Do not use `sp` for anything that must not scale (use `dp`), and never cap font scale to hide a layout problem. Fix the layout.
- Script coverage: Google Fonts families in the library cover Latin (and some Latin-extended). If the app is localized to Indic, Arabic, CJK or other scripts, check coverage and set a fallback family (for example a Noto Sans variant for that script) so glyphs do not fall back to an unrelated system font.

## 5. Shape and elevation

- Material 3 default corner scale: extra small 4dp, small 8dp, medium 12dp, large 16dp, extra large 28dp. The dealt shape scale replaces it consistently (`Shapes` in Compose, `shapeAppearanceCorner*` in XML).
- Components pick their corner size from the scale (buttons are usually full, cards medium or large, sheets extra large on top corners). Do not hardcode radii in screens.
- Elevation levels: 0, 1, 3, 6, 8, 12dp. Use them only for floating things (menus, sheets, FABs, snackbars). Static content separates by tonal surface.
- State layers (hover 8%, focus 10%, pressed 10%, dragged 16%) are handled by the components. Do not rebuild them with ad hoc alpha overlays.

## 6. Dark theme

- Dark is a designed theme, not an inversion. Use the dealt dark roles; do not compute `Color.White` / `Color.Black` swaps in screens.
- Avoid pure black surfaces unless OLED black is a deliberate choice (and then keep elevation visible with the container roles).
- Primary accents are lighter and a little desaturated in dark (the dealt palettes do this via tone 80 instead of 40).
- Check images and illustrations in dark: white backgrounds baked into PNGs glare. Provide night variants or use transparent vectors tinted with theme attributes.
- Follow the system setting by default; offer an in-app override only if the app has a reason.

## 7. Contrast

- Text 4.5:1 (3:1 for large text, 18sp regular or 14sp bold and up); icons, outlines and other meaningful UI 3:1.
- `scripts/contrast.sh '#FFFFFF' '#777777'` for one pair; `--project` for a whole theme.
- Do not communicate state by color alone (add an icon, text or shape).
- Disabled controls are exempt from contrast rules but should still look disabled, not invisible.

## 8. Version notes (verify against the project)

- `surfaceContainer*`, `surfaceBright` and `surfaceDim` exist in recent Compose Material 3 `ColorScheme` and recent Material Components themes. On older versions remove those lines from the dealt files and use `surfaceVariant` or `surface` plus tonal elevation.
- `NavigationSuiteScaffold`, `ListDetailPaneScaffold` and window size class helpers live in the Material 3 adaptive artifacts. Confirm the artifact names and versions in the project's catalog or official docs before adding.
- Predictive back and shared element transitions depend on AndroidX / Compose versions and targetSdk. Confirm support before promising them.
